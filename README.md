# 💡 Світло В Славутичі — віджети

Два способи бачити, де в Славутичі є світло, не відкриваючи сайт:

- **`bot/`** — бот Telegram для мешканців (Cloudflare Worker `svitlo-public`).
  Людина пише боту → отримує «живу картку» (віджет Telegram) з чергами: є світло чи ні, з якого часу,
  графік на сьогодні й завтра. Картки розкриваються натисканням, «⚙️» — вибрати свої черги.
  Картка одна на всіх: коли щось змінюється, бот оновлює її одним запитом — і вона змінюється в усіх чатах.
  Також віддає `/status.json` — дані для застосунку.
  Працює в окремому акаунті Cloudflare (DesperadoAV) зі своєю базою D1 `svitlo-public`.
  Викладається в Cloudflare автоматично (GitHub Actions, `.github/workflows/bot.yml`): сам створює базу й адресу `*.workers.dev`.
  Потрібні секрети репозиторію `CLOUDFLARE_API_TOKEN` (шаблон «Edit Cloudflare Workers» + Account · D1 · Write) і `BOT_TOKEN`.
  **🔔 Сповіщення** (`/notify`): вибрані черги — «світло зникло», «світло з'явилось» і за 10 хв до планового відключення.
- **`app/`** — застосунок для Android (5.0 і новіші) з **віджетом на робочий стіл**: картки черг
  (вибір, розкриття з графіком; стільки, скільки влазить у розмір віджета), кнопки «Мапа черг» і «Сайт».
  Оновлюється раз на 30 хв, кнопкою ↻ і одразу після сповіщення.
  **🔔 Сповіщення** — миттєві, через Firebase (теми `q_<черга>` і `w_<черга>`; бот надсилає одне повідомлення на тему —
  скільки б телефонів не було підписано).
  Збирається автоматично (GitHub Actions, Gradle) і перевіряється на емуляторах; готовий APK — у гілці `app-build`.

Дані бот бере в основного бота `svitlo51` за адресою `/api/status` (версія 4.0.5+, лише стан світла й графіки, без токенів і адрес) —
раз на хвилину, а не на кожну людину. До бази основного бота доступу немає.
Якщо бот для мешканців недоступний, застосунок бере ті самі дані напряму з `svitlo51/api/status`.

## Ліміти Cloudflare (безкоштовно — 100 000 запитів на добу на акаунт)

- основний бот (акаунт a-m-vasylets): +≈1440 запитів на добу від бота для мешканців, скільки б людей ним не користувалося;
- бот для мешканців (акаунт DesperadoAV, свій ліміт): 1440 щохвилинних запусків + кілька запитів, коли людина пише боту,
  + ≈ 48 запитів на добу на кожен телефон із віджетом (раз на 30 хв);
- картки в Telegram оновлюються без запитів до Cloudflare (це запити від бота до Telegram).

## Секрети репозиторію (Settings → Secrets and variables → Actions)

- `CLOUDFLARE_API_TOKEN`, `BOT_TOKEN` — бот;
- `FCM_SERVICE_ACCOUNT` — ключ сервісного акаунта Firebase (бот надсилає сповіщення в застосунок);
- `GOOGLE_SERVICES_JSON` — google-services.json застосунку `ua.svitlo.widget` з того самого проєкту Firebase;
- `ANDROID_KS_B64`, `ANDROID_KS_PASS` — ключ підпису застосунку (той самий, інакше оновлення не встановиться поверх).

## Як оновити

- Бот: зміни в `bot/` → GitHub Actions сам викладає воркер у Cloudflare і налаштовує вебхук.
- Застосунок: зміни в `app/` → GitHub Actions збирає новий APK у гілку `app-build`.
